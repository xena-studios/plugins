# M0: Java 8 bytecode, each server's own text, and Pumpkin waits on upstream (2026-11-24)

The spike (#121) booted real servers for each risky part of the rewrite. Each part's evidence is in `sandbox/m0/<part>/RESULTS.md`.

**Bukkit** (`sandbox/m0/bukkit`). A Kotlin plugin with the stdlib fetched, not shaded, loaded and ran a command on Spigot 1.8.8 (Java 17/21/25), PandaSpigot, Paper 1.8.8, Spigot 1.12.2, Spigot 1.16.5 through `libraries:`, Spigot and Paper 1.21.11, and Folia 26.3.
- **Java 8 bytecode, not 17.** Spigot's launcher refuses newer Java with no override: 1.13.2 above Java 12, 1.16.5 above Java 16. A Java 17 jar would make the real Spigot floor 1.17. Kotlin to Java 8 bytecode ran everywhere, so the core and the Bukkit jar target Java 8; Paper-only code is Java 21 in its own source set.
- **A Java shim as the main class.** It makes the stdlib visible, then loads the Kotlin code by name. On a Java 8 server it says what's needed instead of crashing.
- **How the stdlib is loaded below 1.16.5:** `URLClassLoader.addURL` by reflection on Java 8, through the JDK's trusted lookup on 9+, and a child-first loader as the last resort. Java 25 warns about the lookup, and a later JDK may refuse it; CI watches for that.
- **One Kotlin version across the family.** On 1.8.8–1.14.4, every plugin uses the stdlib of the first plugin that loaded it.
- **`provides:` arrived in 1.15.2,** so below that xMoney can't stand in for Vault and needs Vault.jar.
- **Each server's own text.** One send through `adventure-platform-bukkit` costs about 8 µs on Spigot, against 0.4 µs for Paper's native Adventure. A Bukkit component array cached per language costs 0.07 µs. Paper 1.16.5's bundled Adventure is too old for current MiniMessage. So messages are drawn once per language to the server's own form, and our markup stays our own.
- **Java from Kotlin:** `@JvmOverloads` can't be used on interfaces (write default methods), value classes and function types don't belong in APIs, returned lists must be read-only copies, and `@Throws` is needed for checked exceptions.
- Paper remaps a plugin at startup unless its manifest says `paperweight-mappings-namespace: mojang`; every jar sets it. Paper 1.21.11 spends about 140 ms loading the first stdlib classes, which the startup budget has to absorb or beat.

**Mods** (`sandbox/m0/mods`). A server-side Kotlin Fabric mod (cloud-fabric, Adventure, fabric-language-kotlin) built from one source with Stonecutter for 1.20.1, 1.21.11 and 26.3; each booted, and vanilla clients joined and ran its command.
- Cloud and Adventure releases are tied to one Minecraft version, so Fabric ships one jar per Minecraft line, and Fabric bytecode follows Minecraft's Java (17, 21, 25). Drawing to Minecraft's own text instead of Adventure saves about 1 MB a jar.
- Stonecutter is cheap: 3.3 s to rebuild all three versions; the cold Loom setup (151 s) is cached in CI.
- Sponge (SpongeVanilla 1.21.10, API 17) booted, but Cloud has no Sponge 8+ module, so `platform-sponge` has its own bridge; the stdlib is shaded there and shrunk with R8.
- **Stores.** CurseForge takes Bukkit plugins, mods and Hytale files with one token on three hosts; no existing tool covers all three, so build-logic gets a `CurseForgePublish` task. The Hytale game version id is unconfirmed until a real token is tried. SpigotMC's only API is read-only, and every BuiltByBit write needs Ultimate, as decided.

**Pumpkin** (`sandbox/m0/wasm`). A KMP module (a duration parser, the markup parser, a config class) passed the same tests on the JVM and `wasmWasi`, and ran inside two Pumpkin plugins on `pumpkin-api-kt` 0.1.2, on a Pumpkin built from source (0.2.2, plugin ABI 0.1), one calling the other.
- `common` can't use `java.*`, `String.format`, `synchronized` or threads; `kotlin.time`, `kotlin.uuid` and `Regex` do the job.
- `kotlinx.serialization` works on Wasm. kaml doesn't publish a `wasmWasi` build, but builds for it with a small change to its YAML parser; we get that upstream, or publish our own build meanwhile. The config format stays YAML.
- **A blocker, upstream.** Inside any callback, Kotlin can't reach WASI (files, the clock) because `pumpkin-api-kt`'s bridge holds an allocator WASI needs. Until that's fixed, a Kotlin plugin on Pumpkin can't keep data. M17 waits for it; the core takes the clock and storage from platform interfaces, so nothing else changes.
- Plugins reach each other by sending bytes (`ipc.wit`), so APIs on Pumpkin are serialized requests and replies. Storage is files in the plugin's own folder: no SQL, no shared database, and xBackup can't see the server's worlds there.
- A plugin is 290–520 KB of Wasm, about a Paper jar. It loads in 34–52 ms once Pumpkin has compiled it; the first compile takes about 2.7 s.

**Budgets** (`sandbox/m0/budgets`). Today's 11 plugins, built from `maintenance`, on Paper 1.21.11, each alone and all together, measured with async-profiler, heap after full GCs, and 10 mineflayer bots for two minutes.
- Nine of eleven never showed up on the server thread when idle. Under load the whole family cost 0.023–0.032 ms a tick; `/mspt` varies by ±0.4 ms between identical runs, so budgets are measured by profiling, per plugin, not by `/mspt`.
- What fails the new budgets today: xMoney and xRewind open SQLite on the server thread (enable over 200 ms), xBackup and xMoney poll on their own threads while idle, and xRewind builds a 9.5 MB block-state table at startup. The rewrite's rules already remove the first two.
- The roadmap's 0.5 ms a tick was about 50 times today's worst plugin, so the budget is 0.05 ms; the other numbers are in ROADMAP.md.
- R8 keeps a shaded Sponge jar at 269 KB (from 1,966 KB), once its keep rules cover enums, type tokens, Cloud's service interfaces and listener parameter names. CraftBukkit 1.8.8 and 26.3 behave like Spigot.

**Site** (`sandbox/m0/site`). A fake plugin declared its commands, permissions, config, messages, placeholders and events in a small Kotlin DSL; a Gradle task wrote a manifest and its JSON Schema; the check failed on a changed default (naming the file and line) and on a translation using a tag its message doesn't fill; the docs validated the manifest against the schema and rendered it with seven Starlight components, and `pnpm build` passed. So:
- The DSL lives in `core-common`, the adapters register the same tree with Cloud or Pumpkin, and `plugin.yml`, `fabric.mod.json` and the rest are generated from it.
- Manifests join the golden flow (`-PupdateGolden`), so `./gradlew check` gates them.
- Old majors' docs move to `/<plugin>/v<old>/` rather than versioning the whole site, since plugins reach the rewrite one at a time. Dokka is published for each plugin's latest API only.

M0 is done.
