# The rewrites are merged one by one and released together (2026-11-24)

The owner's call, as xUtilities 3.0 (#123, #167) was ready to merge: each plugin's rewrite merges when it's done, but none is released, not even as an alpha, until every plugin is rewritten. Then they all ship at once, after running on our own servers.

- **A plugin's milestone ends at the merge.** Its "done when" list is everything but running on our servers and the release: merged on `main`, every check green. ROADMAP.md says so, and gains a release milestone after the last plugin (M15) and before the platform waves, whose minors build on released majors. It isn't numbered, so M16 to M20 keep their numbers and their GitHub milestones.
- **What it buys:** the core changes with every plugin, most of all with the first few, and nothing built on an early core is out in the wild to support; owners upgrade once, to plugins that share one tested core. The cost is months between a rewrite and its release, which `maintenance` covers.
- **`maintenance` keeps shipping fixes to today's versions** until then, as it does now (#119). The stores and the site show those.
- **Nothing on `main` publishes the rewrite early.** Releases are tags only (`release.yml`); `<plugin>/modrinth.md`, which `modrinth.yml` publishes to the live store page on every change to `main`, stays today's until the release; so do the README badges and the brand catalog's facts.
- **The site keeps showing the last release.** A merged, unreleased rewrite's line in `docs/src/data/versions.json` has `"unreleased"` (the last release's version and jar budget). `/<plugin>/` then serves the old major's pages at their old addresses, and the new major's are built at `/<plugin>/next/`, link-checked but out of navigation, search and the sitemap, `noindex`. The files sit where they'll be after the release (`<plugin>/` and `<plugin>/v<old>/`), and links are written for then: `src/plugins.ts` serves each file where it belongs now and `src/links.ts` rewrites links on the plugin's pages before the links validator checks them. The switch at the release is deleting `"unreleased"` from that line (docs/README.md, Unreleased rewrites). Checked on xUtilities: every page of main's build is the same but for the moved 2.x pages' edit links and dates, and with the line deleted the site builds as the released 3.0, with 2.x at `/xutilities/v2/`.
- **Versions are the release's, without a pre-release.** xUtilities' build is `3.0.0`, its changelog section `## 3.0.0 (unreleased)` with a note saying so; the release takes both off (the release tasks read a section by its version, so the suffix doesn't stop a dry run).
