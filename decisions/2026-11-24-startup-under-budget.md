# Startup under budget: Paper gets the libraries from our loader, and the startup classes load ahead (2026-11-24)

The first plugin's startup was 271 ms against its 150 ms budget (282 on CI), the `budgets` job's one warning (#162). Both fixes the budgets entry above listed are in, and startup fails the job again when over.

| xSample on an M1 Pro, `scripts/budgets/check.sh`, median of 3 boots | Server's part | onLoad | onEnable | Total |
|---|--:|--:|--:|--:|
| Paper 1.21.11 (Java 21), before | 96 | 20.1 | 138.3 | **252.6 ms** |
| Paper 1.21.11, with `paper-plugin.yml` and its loader | 10 | 15.3 | 112.5 | 137.4 ms |
| Paper 1.21.11, and the startup classes loaded ahead | 10 | 15.3 | 34.5 | **59.5 ms** |
| Paper 26.3 (Java 25), before | 78 | 17.7 | 97.5 | **193.9 ms** |
| Paper 26.3, after both | 4 | 4.3 | 30.2 | **39.0 ms** |

- **On Paper, the jar is also a Paper plugin, whose loader hands Paper the libraries.** The jar carries a `paper-plugin.yml` beside its `plugin.yml`; Paper and Folia from 1.19.3 read it, and Spigot and older Paper never look at it. Its `loader` is the core's `PaperLibraryLoader` (core-loader's `paper` source set, Java 17 class files against Paper's API, never shipped with it), which takes each library in `META-INF/xena/libraries.txt` from the family's cache (`plugins/Xena/libraries/`, downloaded and checked against its pin as the shim does below 1.16.5) and gives it to Paper as a `JarLibrary`. That skips Maven's resolver, which Paper ran over `libraries:` at every boot (about 50 ms of CPU, mostly the resolver's own cold code, the same for one library or five), and Paper's legacy-plugin rewriting of every class (Commodore, and the reflection remapper for `libraries:`), which was a third of onEnable. Today's plugins were Paper plugins already, so this is their model, and the API rules hold: a `plugin.yml` plugin with `depend`, or a Paper plugin with `join-classpath`, sees a Paper plugin's API classes (checked in M1, `sandbox/paper-consumer`). Not chosen: the shim injecting the libraries itself on Paper, which needs the JDK's trusted lookup through `sun.misc.Unsafe` and prints the JDK's warning from Java 24, the Java Paper 26 runs on.
- **The classes a plugin needs as it starts are listed at build time and loaded ahead.** `scripts/budgets/check.sh --record-startup` logs a real boot's class loading (`-Xlog:class+load`) and writes the classes loaded before `Done` from the plugin's jar and its libraries (`startup_classes.py`), the jar's in their names before R8 (from its mapping). The project keeps that as `startup-classes.txt`; `shrinkJar` (R8Shrink) maps it to the shrunk jar's names and puts it in the jar as `META-INF/xena/startup-classes.txt`, leaving out classes R8 removed. The shim's preload thread, which loaded a hand list of the stdlib's biggest classes, now loads that list, without initializing anything, between onLoad and onEnable while the server prepares its worlds. xSample's list is 595 classes (299 of its own, the rest the stdlib's and the YAML parser's). A stale list only costs speed: a class it misses loads when first used, one it names that's gone is skipped. Record it again after a large change.
- **What "loads no classes" means now.** The list is recorded with the default config, so a module that's off by default is never in it. A module that's on by default and turned off by the owner still has its classes defined (not initialized: no static state, listeners or tasks), about what the recorded boot needed; ROADMAP.md's rule is about the runtime cost, which is still nothing.
- **What the number counts.** On Paper with `paper-plugin.yml` there's no `libraries:` line to time, so the loader logs its own time (`-Dxena.startupTimes=true`, through the shim's `Startup times` line: `loader 9.5 ms`), most of it hashing the cached jars against their pins. Paper making the plugin's class loader and loading its main class isn't in it: about 8 ms of CPU in a profile, which no log line bounds. Even counted, startup is under the 100 ms a plugin after the first gets.
- **The Boot workflow fails on startup again** (`--report-only` is gone from the `budgets` job). Booted after these changes: Paper 26.3 with the family test (xSample as a Paper plugin, xTwin with `plugin.yml`), Folia 26.3, and Spigot 1.8.8 on Java 8 with the family test, where the shim downloads the libraries and preloads the same list.
- **For each plugin:** a `paper-plugin.yml` naming `co.xenastudios.<plugin>.core.loader.paper.PaperLibraryLoader` (the relocated name; R8 keeps it, from the file), `api-version: '1.19'`, `folia-supported`, and the `dependencies` Paper plugins declare; and a recorded `startup-classes.txt` beside its build file.
