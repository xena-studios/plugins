# A shrunk jar's translations in one entry, and the release lists read by a field scanner (2026-11-24)

Two size cuts in the core, from xUtilities 3.0's Bukkit jar (#123), which every plugin gets.

- **The shipped `lang/<tag>.yml` files go into one entry, `lang/shipped.txt`.** A jar entry is compressed on its own, so each language's file paid again for what every language repeats: the keys, the markup and the placeholders. `R8Shrink` now writes a jar's two or more translations one after another, each after a `@@ <tag>` line (`@` can't start a YAML line, so no file has one), and core-jvm's `LangFolder.shipped` reads `lang/<tag>.yml` if it's there (a development build, the sources) and the bundle otherwise; `LangFolder.bundle` splits it, for a Fabric mod that reads its own jar through its mod container. xUtilities' seven: 20.7 KiB as files, 14.4 in one entry. Nothing else changes: the files in `src/` are what `checkTranslations` checks, and the plugin's folder gets one file per language as before. Tested in `LangFolderTest`.
- **The release lists are read only as far as the checker needs.** `ModrinthReleases` built a whole JSON tree (maps, lists, doubles) to take three text fields from each version; `JsonReader.objects` now scans for the objects directly inside the top-level array and keeps their top-level text and boolean fields, skipping nested ones (a version's files) and numbers, with no recursion. About 1 KiB in the jar; the parser's tests became the scanner's.
- **Measured and not taken** (xUtilities' Bukkit jar, 508 KiB after these): R8 keeping no `LineNumberTable` would save 30 KiB, but stack traces would lose their line numbers, which [smaller jars](2026-11-24-smaller-jars.md) kept on purpose; `-assumenosideeffects` on Kotlin's `Intrinsics` checks 2.6 KiB, rejected there too. The class files are three quarters constant pool, mostly the JDK's and Kotlin's type names in descriptors, which no setting shortens.
