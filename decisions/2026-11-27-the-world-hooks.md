# The world hooks: block, container and entity changes on every platform, heard only while asked for (2026-11-27)

xRewind 2.0 (M12, #131) logs every block change and puts it back; xLimits 1.0 (M14, #111) stops placements and spawns past a limit. Both need the same thing from each platform, so the core has it first: `co.xenastudios.core.common.world` in core-common, implemented by platform-bukkit (from 1.13) and platform-fabric (1.20.1, 1.21.11, 26.3), and by core-testing's `FakeWorld` for plugins' tests. What was decided:

- **One set of events, platform-neutral.** `BlockChange` (world, x, y, z, `before` and `after` as `BlockData`, a `ChangeCause`, the `player` behind it or a `source` id such as `minecraft:creeper`, `minecraft:water`, `minecraft:fire`), `ContainerChange` (an item and a signed amount), `EntitySpawn` (type, `SpawnReason`, the player where the platform knows), `EntityDeath` (the credited killer) and `EntityChange` (`TAMED`). `BlockData` is the block's `type` at once and its full `data` text (`minecraft:chest[facing=north,...]`, what a logger stores and the platform parses back) only when read; on Fabric there's one per Minecraft state, made once, so a change allocates the event and nothing else. A cause is one of PLAYER, EXPLOSION, FIRE, PISTON, FLUID, ENTITY and DECAY; each has its own event type, so a listener for players' changes never sees a fluid.
- **Nothing listens until a plugin does.** `BukkitPlatform.world(priority)` (an extension in `BukkitWorlds`) and `FabricPlatform.world(priority)` make a `WorldHooks`; it tells the platform to start a kind of change (`WorldHook`: one per cause, containers, hoppers, spawns, deaths, tames) with its first listener and stop with its last, so the fluids' listener, the busiest event there is, exists only while someone wants fluids. Hoppers are their own hook (`onContainerChange(hoppers = true)`), as they were off by default in xRewind 1.x. Where it sits among other plugins is the hooks' priority, as for the chat bridge: a logger asks at `MONITOR` and sees what was decided, a limiter asks earlier and cancels.
- **When it's heard.** A change to air is heard while the block and its contents are still there (a logger reads a chest's items then). A place can already be in the world on Bukkit, which puts the block down before plugins hear it and puts it back if one cancels. Cancelling works where the platform can stop a change cleanly, which `BlockChange.cancellable` says: on Bukkit every change but explosions (where a cancelled block comes out of the blast's list and stays) and pistons (where any cancel stops the piston), and on Fabric a player's places and breaks, pistons, spawns and tames. On Fabric an explosion, fire, a fluid or an entity has already dropped items or taken the block by the time it's set, so cancelling there would duplicate them; those can't be cancelled.
- **Bukkit: the 1.13 API in a source set of its own.** platform-bukkit's main code compiles against 1.8.8; the hooks need block data, which starts at 1.13, so they're the `world` source set, compiled against Spigot 1.13.2's API and built on main's classes (main never names them, so there's no cycle; they go out in the jar and in the classes a plugin compiles against). `world()` throws below 1.13, so an older server never loads them. Each hook is one listener object of Bukkit events registered with `registerEvent` while it's on: places (with `BlockMultiPlaceEvent`'s parts), breaks, ignites, buckets and trampling for PLAYER; `EntityExplodeEvent` and `BlockExplodeEvent` (TNT put down to who lit it); `BlockBurnEvent`; piston extend and retract (each block's new spot, and the spots left empty); `BlockFromToEvent` (only what a fluid destroys); `EntityChangeBlockEvent`; `LeavesDecayEvent`; inventory open and close, compared (one event per kind of item a visit changed, a double chest as its left half); `InventoryMoveItemEvent`; `EntitySpawnEvent` (and the creature, item and projectile events under it), `EntityPlaceEvent` and `HangingPlaceEvent` as PLACED, with the player from `EntityBreedEvent`, a spawn egg's click or the placing event; `EntityDeathEvent`; `EntityTameEvent`. Paper's `BlockDestroyEvent` (a torch falling off a broken block) is found by name and heard while players' or explosions' changes are, put down to whoever broke the block beside it in the last second, as xRewind 1.x did. Paper-only methods (`getHolder(false)`, `getExplodedBlockState`) are found once, as method handles. Folia fires each of these on the region that owns the block, so the hooks are region-correct as they are.
- **Fabric: mixins, the first in the core.** Fabric API has player breaks and deaths but nothing for explosions, fire, fluids, pistons or spawns, so the hooks are mixins (`co.xenastudios.core.fabric.mixin`, Java): one on `Level.setBlock`, which every block change goes through, and around the methods that make changes for a reason (`ServerPlayerGameMode.destroyBlock`, `useItemOn` and `useItem`; the explosion's block pass, `Explosion.finalizeExplosion` before 1.21.2 and `ServerExplosion.explode` after; `FireBlock.tick`; `FlowingFluid.spreadTo`; `ServerLevel.tickNonPassenger`; the spawners, breeding, eggs, spawn eggs, dispensers and `/summon`), which push a frame saying who's acting for `WorldPoints`; `setBlock` asks the top frame whose change it is. A change with no frame (crops, redstone, worldgen, a plugin's own rollback) is no one's and isn't heard. Pistons are heard from Minecraft's own `PistonStructureResolver` before they move, and their own sets meanwhile aren't heard again. Spawns are `ServerLevel.addFreshEntity`, tames `TamableAnimal.tame` and `AbstractHorse.tameWithName`, containers `ServerPlayer.openMenu` and `doCloseContainer` with the block the player clicked, hoppers `HopperBlockEntity.addItem`. MixinExtras' `@Share` (Fabric Loader has had it since 0.15) carries "did I push" from a method's start to its end; frames left by a method that threw are dropped each tick.
  - **Cost.** Every mixin reads one static field first, `WorldPoints.heard`, the bits of the hooks some listener wants; with nothing listening that's the whole cost, on `setBlock` too. Frames are kept on the server thread only, in arrays made once.
  - **Only in mods that ask.** A mod's jar carries the mixins and their config only with `xenaFabricMod { worldHooks = true }`, as `<id>-world.mixins.json` in the mod's own relocated package, which its `fabric.mod.json` lists under `mixins`; without it R8 drops them, and no other mod's server changes. Each mod's relocated copy has its own `WorldPoints`, so two mods' hooks never meet.
  - **How they're built.** No refmap: the mixins are written in Mojang's names and remapped with the mod's jar by Loom's `remapJar` (tiny-remapper's mixin support, Loom 1.19's default), which a refmap's class names couldn't follow through the relocation; from 26.1 nothing is remapped. R8 never sees them (`R8Shrink` leaves out the packages of the mixin configs `fabric.mod.json` lists, gives them to R8 as class path, keeps what they call, and copies them into the shrunk jar as they are), since R8 would drop the annotations Mixin reads. Their config requires every injection (`defaultRequire: 1`), so a Minecraft line whose methods moved fails its boot rather than losing a hook quietly.
- **Checked on real servers.** xSample's checks: on Bukkit (`WorldCheck`, with `-Dxsample.world=true`, which its `boot.sh` passes and the budget check doesn't, so its startup and metaspace stay a plugin's without the hooks) an explosion destroys a block it put down and a logger at `MONITOR` hears it as the explosion's, a zombie's spawn is stopped and doesn't happen, and with the listeners gone the plugin has none left registered with Bukkit; before 1.13 `world()` must refuse. Passed on Paper 1.21.11, Folia 26.3 and Spigot 1.13.2. On Fabric, as the server starts: a block set with no one behind it isn't heard, the explosion is, and an item's spawn is stopped; passed on Fabric 1.20.1, 1.21.11 and 26.3, every mixin applied. Spigot 1.13.2 also logs an error converting the jar's Paper loader class (Java 21 bytecode its class converter can't read); that comes from the loader, not the hooks, and the nightly Spigot 1.13.2 cell already fails on `main`.
- **Not yet.** Player trampling on Fabric (it happens in the player's movement packet, outside any frame); a block explosion's source on Fabric and Spigot is `minecraft:explosion`, not the bed; NeoForge and Forge get their own mixins with M16.
