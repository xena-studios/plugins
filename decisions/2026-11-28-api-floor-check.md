# Each shrunk Bukkit jar is checked against its floor's API (2026-11-28)

Part of #111. A rewritten plugin's Bukkit adapter compiles its main code against its floor's API (Spigot 1.8.8, or 1.13.2 for xLimits and xRewind), so the compiler refuses a plain call to something newer. Nothing checked the jar that ships, which R8 makes. #238 found one way that goes wrong: R8, shrinking against Paper's API, where every `EntityType` is `Keyed`, turned `(type as? Keyed)?.key` into a direct `EntityType.getKey()`, which 1.13 hasn't, so every entity spawn on Spigot 1.13.2 threw `NoSuchMethodError`. The JVM links a call when it first runs, so the plugin started and its boot checks passed; only a real client spawning a mob found it.

- **`checkApiFloor`, part of `check` on every `:bukkit` project with `xena.r8`** (build-logic's `ApiFloor`), reads every class, method and field the shrunk jar names in the server's packages (`org.bukkit`, `org.spigotmc`, `com.destroystokyo`, `io.papermc`, `net.kyori`), and looks each up in the project's compile classpath, which is the floor's API, up the class hierarchy (the jar's own classes, the floor's, and the JDK's). A member is looked up by name and descriptor, as the JVM links it.
- **What's left is listed, per plugin, in `<plugin>/bukkit/api-floor.txt`:** the calls made only once a check at startup has found what they need (Folia's schedulers, Paper's loader and Adventure, the `modern` source sets). 24 to 57 lines a jar when this landed, every one of them in code behind such a check. A new line fails the build until it's added to the file, so it's looked at in review; a line the jar no longer needs fails too, so the file stays the jar's. `updateApiFloor` writes the file from the jar. A failure names the source classes using the member, from R8's mapping.
- **What it doesn't check.** Whether a guarded call is right on every server its guard lets in: the file says "only after checking", and the check is the code's. A member whose kind changed (xTeleport's `Biome`, an enum before 1.21.3 and an interface after: `invokeinterface` on an enum, `IncompatibleClassChangeError`) is looked up by name, not kind. The JDK: a Java 8 jar calling something from a newer JDK. Fabric's jars, which Loom remaps against one Minecraft line each and which boot on that line.
- **Measured.** A few seconds a jar on top of R8. `ApiFloorTest` reproduces #238's call on a small 1.13 API (found), the same call through `Keyed` (not found), and a member the plugin's own class inherits from the server's.
