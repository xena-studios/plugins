# The Paper loader is Java 8 class files and never in the startup list (2026-11-28)

Part of #162. The nightly Boot run failed three nights running (25 to 27 November) on Spigot 1.13.2: `Fatal error trying to convert xSample v0.0.0:co/xenastudios/xsample/core/loader/paper/PaperLibraryLoader.class`. Every rewritten plugin's Bukkit jar had the same class at the same Java 17 class-file version (61, the jar's only class above 52) and listed it first in its startup list, so each would have failed there in the same way. Only xSample showed it because its boot runs first and the cell stops at the first failure. That blocked xRewind and xLimits, whose floor is 1.13.

- **Why it showed on 1.13.2 only.** Spigot's Commodore (1.13 on) rewrites each class a plugin's class loader loads, with the ASM of its day. ASM in 1.13.2 can't read Java 17 class files, so it logs that error. ASM in 1.16.5 and in newer Spigot can read them; there the class just fails to load, because Paper's API isn't on those servers. Nothing on Spigot uses the class. It was loaded only because the startup list, recorded on Paper, names it, and the shim preloads that list on every server.
- **The fix, in two parts, each of which is enough alone:**
  - **The class is compiled to Java 8 class files**, like the rest of the jar (core-loader's `paper` source set, `-source 8 -target 8` against Paper's Java 21 API, which `--release 8` can't read). Commodore of every version can read it, and Paper runs it as before: it only implements Paper's `PluginLoader` and uses nothing of Java's newer than 8.
  - **It's never in the jar's startup list.** build-logic's `R8Shrink` leaves out `co.xenastudios.<plugin>.core.loader.paper.*` whatever the recorded list says, and `scripts/budgets/startup_classes.py` no longer records it. Paper loads the loader in a class loader of its own, before it makes the plugin's. Preloading it in the plugin's loader therefore only defined a second copy on Paper, and on every other server it loaded a class for an API that server doesn't have. The recorded `startup-classes.txt` files keep the line (it's dropped at build time), so no plugin's list needs recording again.
- **Nothing new loads at startup.** On Paper, one class fewer is preloaded. Paper's library loader and the libraries it hands over are unchanged.
- **Spigot 1.16.5 had another cause, in xTeleport alone.** Its `modern` source set is compiled against Paper's API, where `Biome` is an interface (since 1.21.3), so `world.getBiome(x, y, z).key` became an `invokeinterface` on `Biome`. On 1.16 to 1.21.2, where `Biome` is an enum, that throws `IncompatibleClassChangeError`, and the RTP check never found a spot. The fix calls `getKey` through `Keyed`, which `Biome` implements on both sides of 1.21.3.
- **Spigot 1.13.2 also showed one in xMarket alone**, found by booting every rewritten plugin there: its price list's item scan (`Modern.items`, 1.13 on) called `Material.isAir`, which is 1.14 on (`NoSuchMethodError`). Air is now told by name (`AIR`, `CAVE_AIR`, `VOID_AIR`).
- **Pull requests still don't boot 1.13.2 or 1.16.5.** Their cells are the floor and the newest. The nightly run, also run by hand on this change, boots them.
