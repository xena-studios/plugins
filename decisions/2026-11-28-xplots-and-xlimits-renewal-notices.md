# xPlots 2.0 registers no xLimits provider; renewal notices are stored with the plot (2026-11-28)

Two gaps left by xPlots 2.0 ([xPlots 2.0](2026-11-28-xplots-2.md)), as part of M13 (#132):

- **No per-plot xLimits provider in 2.0; xLimits' docs corrected.** xLimits' FAQ said xPlots 2.0 would register a `LimitProvider` for its plots. It doesn't, and xLimits' FAQ now says a plot or claim plugin can do this, not that xPlots does. Why not now: xLimits counts per chunk, and a provider can only change the per-chunk limit at a location. It can't make a plot its own scope, counted across the chunks it spans. xPlots 2.0 also has no per-plot limit to give it, no setting like "a bigger plot allows a bigger farm", and adding one is a feature with its own config, menu and migration questions. It would also need a reflection bridge, because each plugin relocates its own core and xLimits' `LimitProvider` takes xLimits' core's `Location` (as xPlots already does for xMoney and xTeleport). A real per-plot scope needs xLimits to count by area as well as by chunk. That's a change to xLimits' API, for a later minor of both, if owners ask for it. Not chosen: a provider that only exempts plots or scales the chunk's limit by a constant. It would put a setting in xPlots that does less than it seems to.
- **Renewal notices survive a restart.** When an auto-renewal, or a renewal the balance didn't cover, happens while the owner is away, the notice was kept only in memory. A restart before they joined lost it. It's now a row in a new `{p}notice` table, made beside the schema like `{p}renewal` (`CREATE TABLE IF NOT EXISTS`, so the schema stays 1 and the 1.x jar ignores it). There's one row per plot and owner: the latest message's key (`renewed`, `renew-failed`) and the price. It's read with the plots at start, delivered as the owner joins, and deleted once told; `/xplots forget` removes it too, and deleting the plot or field takes it with them. It's a table of its own, not a column on `{p}renewal`, so a renewal table made by an earlier 2.0 build is left as it is. The notice is told only about a plot that's still the owner's. A failed renewal followed by the plot running out isn't told after the fact, the same as `expired` (to the owner only if online), which is 1.x's behaviour. The time left in `renewed` is worked out as it's told. Tested across a restart (`anAwayOwnersRenewalNoticeSurvivesARestartAndIsToldOnceAsTheyJoin`).
