Current version: **2.0.0**

xBans is a punishment plugin: bans, temporary bans, IP bans, mutes, warnings and kicks, with history, alts and staff limits. Every ban and mute in force is checked from memory, so the join check never waits on your database and nothing gets round a mute.

- **Every feature free.** No premium version, no early-access builds, nothing behind a Patreon.
- **Bans that hold.** Every ban and mute in force is kept in memory, loaded before anyone can join, so the join check never waits on the database and keeps working if MySQL drops for a moment. A ban made while someone is connecting still catches them. Mutes block chat, `/msg`, `/r`, `/me` and the rest (by any alias, `/essentials:msg` included), signs, books and anvil renames.
- **Bans for the whole network.** With xBans on Velocity or BungeeCord too, a banned player is turned away at the proxy and never reaches a server, and a ban made on any server takes them off the network at once. See [Networks](/xbans/networks/).
- **Nothing is ever deleted.** An unban is recorded next to the ban, with who, when and why. Only `/prunehistory` deletes, when you ask it to.
- **Templates and escalation.** `/ban Steve hacking` gives 7 days, then 30, then permanent. Three warnings can mute for an hour. All in the config.
- **Staff limits.** Weights so helpers can't ban moderators, and longest durations per group.
- **In your players' languages.** Ban screens, mute notices and every reply reach each player in their client's language: English, German, Spanish, French, Brazilian Portuguese, Russian, Polish or Simplified Chinese. A ban screen is drawn in the language the player last played in.
- **Easy to switch to.** LiteBans' command syntax: `/ban Steve -s 7d server:survival Hacking`, `/tempmute Alex 1d2h`, `/unban #123`, with silent (`-s`), extra silent (`-S`) and public (`-p`) punishments and server scopes, so staff habits carry over. Your LiteBans, AdvancedBan, vanilla and EssentialsX bans come across with one command: see [Switching](/xbans/switching/).

:::note[Coming from xBans 1.x?]
Replace the jar and restart: your punishments, history and IP records are read as they are, your config is carried forward, your edited messages move to `lang/en.yml`, and the old file is kept as `config.yml.bak-v1`. See [Upgrading from 1.x](/xbans/upgrade/).
:::

## Where it runs

One jar for every Bukkit-family server from 1.8.8 to the newest, Folia included, a jar per Minecraft line on Fabric (server-side only: players install nothing), and a jar each for Velocity and BungeeCord.

| | |
| --- | --- |
| **Paper and Folia** | Bans are checked before the player's connection is accepted; on newer Paper, before they're even configured. Chat is checked in Paper's own chat event, and every other plugin's chat listener, the old one included, sees a muted player's message cancelled. |
| **Spigot and CraftBukkit** | The same checks through Bukkit's events. Anvils say what's typed from 1.11, so a mute blocks renames from then on. |
| **Fabric** | A banned player is refused at login, and a mute blocks chat, Minecraft's `/me` and `/say`, and [zChat](/zchat/)'s `/msg` and `/reply`. Minecraft has no event before other commands run (its own `/msg` among them), nor for signs, books or anvils, so the rest of `mutes` applies on Bukkit. |
| **Velocity and BungeeCord** | xBans on the proxy, sharing the servers' MySQL database, turns banned players away before they reach a server and keeps them off the servers they're banned on. See [Networks](/xbans/networks/). |
| **zChat** | [zChat](/zchat/) reads xBans' mutes, so a muted player can't chat or `/msg` through it either, on every server of a network. |

## You won't feel it running

The join check and the chat check are a couple of lookups in memory each: no database query, no waiting. Punishments are written by one background thread. History pages are read by key range, so the 300th page of a long history is as quick as the first. There are no repeating tasks on a single server; network mode adds one check every few seconds, off the server's threads.

## Storage

SQLite out of the box, in one file in the plugin's folder, or MySQL/MariaDB for networks. The tables are 1.x's, so going back to 1.0.1 reads them as they are. See [Configuration](/xbans/configuration/#storage).

## What else it does

- **IP privacy.** IPs can be stored as salted hashes: alts and IP bans still work, with no list of addresses to leak. See [Privacy](/xbans/privacy/).
- **A staff layer for other plugins.** Who's staff, staff notifications and silent punishments, through the [API](/xbans/developer-api/), for vanish and moderation plugins to build on.
- **Replaces vanilla** `/ban`, `/pardon`, `/ban-ip`, `/pardon-ip`, `/kick` and `/banlist`.
- **Every change applies on reload**, even switching to another database. No restarts.

## Getting started

3. Set up templates, staff limits and what mutes block: [Configuration](/xbans/configuration/).
4. Coming from LiteBans, AdvancedBan, EssentialsX or vanilla bans? Bring them: [Switching](/xbans/switching/).
