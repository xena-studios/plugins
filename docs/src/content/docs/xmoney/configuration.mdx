The config is `plugins/xMoney/config.yml` (`config/xmoney/config.yml` on Fabric), written on first start. Apply changes with `/xmoney reload`: everything applies, including turning commands on or off and changing aliases and permissions, except `storage` and `network`, which are read once at startup. A bad value falls back to its default with a warning in the console; xMoney never stops over config. xMoney's messages are in `lang/`: see [Messages](/xmoney/messages/).

| Section | What it's for |
| --- | --- |
| `messages` | The language and the theme, `shared` with every Xena plugin unless set here. |
| `currency` | The currency's names, symbol, decimals and how amounts are written. |
| `starting-balance`, `max-balance` | What a new player has, and the most an account can hold. |
| `commands` | Each command's switch, aliases and permission, and `/pay`'s minimum and confirmation. |
| `ledger` | How long the ledger's lines are kept. |
| `storage` | Where balances and the ledger are: SQLite, MySQL/MariaDB, or the family's shared database. |
| `network`, `network-wait-ms` | Several servers sharing balances: [Networks](#networks). |
| `updates` | The update checker. |

## Amounts

Money is counted in ten-thousandths, whatever `currency.decimals` says: the decimals are for showing amounts and for what's typed into commands. Other plugins' amounts keep all four places, so a price split in two costs what it would whole. Past four places, what's paid in is rounded down and what's taken is rounded up, so rounding never makes money. Lowering `decimals` later keeps the parts of balances it no longer shows.

## Storage

SQLite out of the box: one file, `money.db`, in the plugin's folder, with nothing to set up. `mysql` (or MariaDB) is for networks, or servers with a lot of history; `shared` keeps xMoney's tables in the database every Xena plugin can share, set in `plugins/Xena/config.yml`. Balances aren't copied from one to another when you change it: [import](/xmoney/switching/) or move them yourself. The tables are 1.x's, unchanged, so the [1.x jar](/xmoney/upgrade/#going-back-to-101) reads them too.

## Networks

For several servers sharing balances through one MySQL or MariaDB database: the same `storage` settings and `table-prefix` on each, and `network.enabled: true`. A change on one server reaches the others within `check-every` seconds. **Experimental:** a withdrawal is decided by the shared database, so a shop's Vault call waits for it on the server thread, at most `network-wait-ms` (50 ms by default, never above 250) to be taken up, and while the database is away, withdrawals are refused at once. Money is never lost, made or taken twice either way: a payment the database didn't take up in time is refused and never taken later, one it took is waited for, and a commit whose answer was lost is looked up, never run again.

## Make it look like your server

`messages.theme` sets the look of every message xMoney sends: a prefix, the text colour, and three styles. Each is `shared` until you set it, which takes the value every Xena plugin shares, in `plugins/Xena/config.yml`.

```yaml
messages:
  theme:
    prefix: "<dark_gray>[<gradient:#10AC79:#5EE08A>Bank</gradient>]</dark_gray> "
    highlight: "<gold>"
```

`messages.language` is `auto` by default (through `shared`): each player reads xMoney's messages in their client's language, and the console in `default-language`. A config carried forward from 1.x with messages you'd edited is set to `en`, so your words are what everyone sees, as before.
