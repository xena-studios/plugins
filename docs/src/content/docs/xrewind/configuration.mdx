The config is `plugins/xRewind/config.yml`, written on first start. Apply changes with `/xrewind reload`. xRewind is being built, so settings will be added before 1.0.

| Section | What it covers |
| --- | --- |
| `theme` | The prefix and colours xRewind's messages share: see [the theme](/start/formatting/#the-theme). |
| `messages.error` | Shared errors: players only, no permission, player not found, wrong usage, and a command that hit an error. |
| `messages.lookup` | What lookups and the inspector say, and the words for each kind of change. |
| `messages.rollback` | What rollbacks, restores, previews and undo say. |
| `storage` | Where the history is kept: SQLite in the plugin's folder (`history.db`), or MySQL/MariaDB. |
| `rollback` | How fast rollbacks work, and how far they reach without `xrewind.rollback.global`: see [Rolling back](/xrewind/commands/#rolling-back). |
| `log` | What's logged. Something that's off isn't listened for at all, so it costs nothing. |
| `update-checker` | Checks Modrinth for a new version once a day: [Privacy](/start/privacy/). |

## Storage

`type: sqlite` needs nothing set up. Use `type: mysql` (it works with MariaDB too) for a network, or a server with a lot of history, and fill in `mysql`. `table-prefix` goes in front of every table's name, so several servers can share one database by giving each its own prefix.

The database is opened in the background, so a slow or unreachable MySQL never holds up startup. If it can't be opened, the console says why; fix the settings and run `/xrewind reload`. Changing `storage` on a reload switches to the new database, and a reload that can't open the new one keeps using the old one. History isn't copied between databases.

A bad value falls back to its default with a warning in the console.
