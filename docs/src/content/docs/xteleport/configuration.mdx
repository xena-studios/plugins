The config is `plugins/xTeleport/config.yml` (`config/xteleport/config.yml` on Fabric), written on first start. Apply changes with `/xteleport reload`: everything applies, including turning commands on or off and changing aliases and permissions, except `storage`, which is read once at startup. A bad value falls back to its default with a warning in the console; xTeleport never stops over config. xTeleport's messages are in `lang/`: see [Messages](/xteleport/messages/).

| Section | What it's for |
| --- | --- |
| `messages` | The language and the theme, `shared` with every Xena plugin unless set here. |
| `commands` | Each command's switch, aliases and permission, and for the teleports their cooldown and cost. |
| `teleports` | The warmup, whether damage cancels it, and the safe-arrival check. |
| `homes` | How many homes players may have, the default home's name, the bed home and `/homes`' page size. |
| `tpa` | How long a request lasts. |
| `warps` | Per-warp permissions and `/warps`' page size. |
| `spawn` | Whether players arrive at the spawn when they first join, every join, and when they respawn. |
| `rtp` | `/rtp`'s worlds, their radii, the attempts, the cooldowns and the limit on searches at once. |
| `storage` | Where homes and warps are: SQLite, MySQL/MariaDB, or the family's shared database. |
| `updates` | The update checker. |

## Costs

A command's `cost` is taken once the warmup is over and the spot checked, from whoever asked (for `/tpahere`, the player who sent the request, not the one who moves), and given back if the teleport then fails. It goes through [xMoney](/xmoney/) when it's installed, in its ledger as "Teleport: home" and so on; on Bukkit without xMoney, through whatever economy is registered with Vault, as 1.x did. `xteleport.cost.bypass` skips every cost.

## RTP

Each world under `rtp.worlds` is searched in a ring between `min-radius` and `max-radius` blocks from its spawn point (or `center-x` and `center-z`), inside the world border. A world that isn't listed, or has `enabled: false`, can't be picked. On Fabric a world's name is its dimension (`minecraft:the_nether`); `world`, `world_nether` and `world_the_end` mean the vanilla three there too, so the defaults work everywhere. Try a world's settings with `/xteleport rtpcheck <world> 10`.

## Storage

SQLite out of the box: one file, `xteleport.db`, in the plugin's folder, with nothing to set up. `mysql` (or MariaDB) keeps homes on a database server; `shared` keeps xTeleport's tables in the database every Xena plugin can share, set in `plugins/Xena/config.yml`. Homes aren't copied from one to another when you change it. The tables are 1.x's, unchanged, so the [1.x jar](/xteleport/upgrade/#going-back-to-101) reads them too.

## Make it look like your server

`messages.theme` sets the look of every message xTeleport sends: a prefix, the text colour, and three styles. Each is `shared` until you set it, which takes the value every Xena plugin shares, in `plugins/Xena/config.yml`.

```yaml
messages:
  theme:
    prefix: "<dark_gray>[<gradient:#CE41E3:#5EE08A>Travel</gradient>]</dark_gray> "
    highlight: "<gold>"
```

`messages.language` is `auto` by default (through `shared`): each player reads xTeleport's messages in their client's language, and the console in `default-language`. A config carried forward from 1.x with messages you'd edited is set to `en`, so your words are what everyone sees, as before.
