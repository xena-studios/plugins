The config is `plugins/xUtilities/config.yml` (`config/xutilities/config.yml` on Fabric), written on first start. Apply changes with `/xutilities reload` (or `/xu reload`): everything applies, including turning commands on or off and changing aliases and permissions. A bad value falls back to its default with a warning in the console; xUtilities never stops over config. The messages are in `lang/`: see [Messages](/xutilities/messages/).

## Make it look like your server

`messages.theme` sets the look of every message: a prefix, the text colour, and three styles the messages use as tags. Each is `shared` until you set it, which takes the value every Xena plugin shares, in `plugins/Xena/config.yml`: set it there to restyle the whole family, or here for xUtilities alone.

```yaml
messages:
  theme:
    prefix: "<dark_gray>[<gradient:#B48CFF:#5EE08A>MyServer</gradient>]</dark_gray> "
    highlight: "<gold>"
```

## Language

`messages.language` is `auto` by default (through `shared`): each player reads xUtilities in their client's language, and the console in `default-language`. Set it to one language, such as `language: en`, to give everyone the same. A config carried forward from 2.x with messages you'd edited is set to `en`, so your words are what everyone sees, as before.

## Turn off what you don't need

Every command has `enabled`, `aliases`, `permission` and, with a `[player]` form, `permission-others`:

```yaml
commands:
  fly:
    enabled: false        # /fly is gone: not registered, not in tab completion
  speed:
    aliases: ["setspeed", "zoom"]
  ping:
    permission: ""        # anyone, with no permission at all
```

`info-commands` holds `/discord`, `/store`, `/website` and any you add: see [Link commands](/xutilities/link-commands/).
