Current version: **2.0.0**

xVote receives votes from server lists and rewards players for them, in one plugin. It's for servers that would otherwise run one plugin to receive votes and another to reward them, and it pays every vote exactly once, even across a network.

- **Every feature free.** No premium version, no early-access builds, nothing behind a Patreon.
- **A Votifier built in.** It speaks Votifier v1 and v2, byte for byte as NuVotifier does, on its own threads, with limits that keep floods and slow connections out. See [Setting up](/xvote/setting-up/).
- **Every vote paid once.** Each vote is a row in a ledger, and one server takes it before it's paid. Offline players are paid when they join; a name that has never joined waits until it does.
- **Votes for the whole network.** With xVote on Velocity or BungeeCord, the proxy is the network's one receiver: one port for every list, and each vote paid on the server the player is on, or the first one they join. See [Networks](/xvote/networks/).
- **Rewards your way.** Money (through [xMoney](/xmoney/), or Vault's economy on Bukkit), items, commands, messages, broadcasts and sounds, with a chance each. Give them on every vote, per site, on the first vote of the day, every Nth vote, at streak milestones and at vote totals. Other plugins can add reward types.
- **For players.** `/vote` lists each site with a link and when it opens again. `/vote top` has today's, this week's, this month's and all-time leaderboards. Reminders when they join, a vote party for everyone, and every reply in their own language.
- **Easy to switch to.** It takes over NuVotifier's keys and tokens on its first start, so your lists keep working, and imports every player's total from VotingPlugin or SuperbVote. See [Switching](/xvote/switching/).

:::note[Coming from xVote 1.x?]
Replace the jar and restart: your votes, totals, keys and tokens are read as they are, your config is carried forward, your edited messages move to `lang/en.yml`, and the old file is kept as `config.yml.bak-v1`. See [Upgrading from 1.x](/xvote/upgrade/).
:::

## Where it runs

One jar for every Bukkit-family server from 1.8.8 to the newest, Folia included, a jar per Minecraft line on Fabric (server-side only: players install nothing), and a jar each for Velocity and BungeeCord.

| | |
| --- | --- |
| **Paper and Folia** | Rewards are given on each player's own thread. Reward items take `/give`'s item text, components included, and what doesn't fit waits for `/vote claim`. |
| **Spigot and CraftBukkit** | The same, with items by name (`diamond`, `wool:14` on old versions) before 1.20.5, whose servers read components. |
| **Fabric** | Items go through Minecraft's own `/give` (what doesn't fit drops at the player's feet, as `/give` does) and sounds through `/playsound`. Money through xMoney. |
| **Velocity and BungeeCord** | The network's receiver: it stores and counts each vote in the database the servers share, and the player's server pays it. See [Networks](/xvote/networks/). |

## How it works

A server list sends a vote to xVote's **receiver**, on its own port. The vote names a player and the list it came from (its **service**). xVote finds the player, stores the vote, and gives the rewards it earned. If the player is offline, the vote waits and is paid when they join.

A vote from the same site sooner than that site's **cooldown** is a repeat and is dropped. Sites you haven't listed have one too, `counting.unlisted-cooldown-hours` (24 by default). So is a replayed vote with the same timestamp.

**Totals** are counted per day, week and month, in the time zone you set, plus all time. A **streak** is the days in a row a player has voted.

## Storage

Votes are kept in SQLite out of the box, in `plugins/xVote/votes.db`, or in MySQL/MariaDB. Several servers (and the proxy) can share one MySQL database: see [Networks](/xvote/networks/). The tables are 1.x's, so going back to 1.0.1 reads them as they are.

## What else it does

- **You won't feel it running.** Totals and leaderboards are kept in memory; the database is written on its own thread. On a single server nothing repeats unless you turn on timed reminders; network mode adds one check every few seconds, off the server's threads.
- **Every change applies on reload**, sites and rewards included. Only `storage` and `network` wait for a restart.
- **For developers:** totals, leaderboards, reward types and cancellable events, the same on every platform. See [Developer API](/xvote/developer-api/).
