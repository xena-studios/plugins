# The rewrite's runtime budgets (ROADMAP.md, "Fast, robust, light"), checked on a real server by
# scripts/budgets/check.sh, which fails when a plugin is over one: "<name> <limit>", one a line.
# The jar budgets are gradle/jar-budgets.txt; the benchmarks' are core/core-benchmarks/budgets.txt.

# Startup: the plugin's time on the server thread at every boot (its libraries: resolved by the
# server, or on Paper its paper-plugin.yml loader handing them over; onLoad; onEnable), median of
# the timed boots. The first Xena plugin to start pays for loading the Kotlin stdlib's first classes.
startup-first-ms 150
startup-ms 100
# On a proxy (scripts/boot-proxy.sh --startup-budget, in the Boot workflow's proxy cells) the same
# first-plugin budget, for the shim's own line: libraries checked and added, the plugin enabled.

# Idle, no players: server-thread time a tick, and CPU time a second on every other thread, in
# stacks that pass through the plugin's package.
idle-tick-ms 0.001
idle-offthread-ms-per-s 0.5

# Under load (10 bots): the same, per plugin and for every plugin of the run together.
load-tick-ms 0.05
load-family-tick-ms 0.25
load-offthread-ms-per-s 2

# Heap that only the plugin's own class loader keeps alive (its objects, its classes, and what
# only it holds: its libraries: loader on Paper included), from a heap dump of the idle server
# (scripts/budgets/Retained.java), per plugin. 2.4 MB, not ROADMAP's first 4 MB: that was over the
# server without plugins, which carried about 1 MB of the server's own per plugin and moved by
# 2 MB from boot to boot; this way a plugin keeping 2 MB more fails, the lightest too
# (decisions/2026-11-28-the-heap-budget-is-what-a-plugin-retains.md). And metaspace in the
# plugins' own class loaders (their jars; libraries: are reported, not budgeted).
heap-mb 2.4
metaspace-mb 1.5
# Our classes' instances after the load against before it: the larger of the two allowances.
heap-growth-percent 10
heap-growth-mb 0.5
